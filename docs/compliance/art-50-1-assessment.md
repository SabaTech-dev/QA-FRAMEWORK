---

## 1. Scope of Article 50(1)

Article 50(1) requires that providers ensure AI systems **intended to interact directly with natural persons** disclose that the person is interacting with an AI system, unless this is obvious from the circumstances.

**Obligation trigger:** The AI system must be designed to interact *directly* with a person (e.g., chatbot, conversational agent, voice assistant).

### 2.2 User Interaction Model

QA-FRAMEWORK is a **QA automation SaaS platform**. Users interact with:

- **Web Dashboard** — project management, test configuration, results visualization
- **REST API** — programmatic access for CI/CD integration
- **CLI** — local test execution

**No chatbot, conversational interface, voice assistant, or real-time AI dialogue** exists in the system. LLMs are used as **backend processing tools** for generating test cases, analyzing code, and evaluating test quality — not as direct interlocutors.

### 2.3 Data Flow

```
User → Dashboard/API → Backend Service → [LLM called as tool] → Results returned to user
```

The LLM is invoked as a **subroutine** within backend processing. The user never interacts with the LLM directly. The output is processed, structured test code — not a conversational response from an AI.

## 3. Assessment

### 3.1 Conclusion: Article 50(1) Does NOT Apply

QA-FRAMEWORK does not qualify as an AI system "intended to interact directly with natural persons" under Article 50(1). The system is a **QA automation tool** that uses LLMs as internal components. Users interact with a software platform, not with an AI conversational agent.

### 3.2 Related Obligations to Consider

While Art. 50(1) does not apply, other transparency provisions may be relevant:

| Article | Relevance | Status |
|---------|-----------|--------|
| **Art. 50(2)** — AI-generated content labeling | ⚠️ Test code generated by AI is output to users. Consider labeling AI-assisted test generation in the UI. | **Review needed** |
| **Art. 50(3)** — Deep fakes disclosure | ❌ Not applicable (no synthetic media generation) | N/A |
| **Art. 13** — Transparency to deployers | ⚠️ Technical documentation about LLM usage should be available to enterprise customers | **G3 inventory covers this** |

### 3.3 Recommendation

Although Art. 50(1) does not strictly apply, as a best practice for compliance posture and customer trust:

1. **Add an "AI-assisted" badge** in the test generation UI when tests are created using LLM-generated content
2. **Document the LLM pipeline** in technical documentation (fulfills Art. 13 obligations to deployers)
3. **Track this as a G3 (August 2027) item** rather than G1 (August 2026)
